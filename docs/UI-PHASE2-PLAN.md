> 2026-11-02 作成。オーナーの要望と確認した答えをもとにした計画。実装したら各項目に（済）を付け、
> 実装の記録は UI-PHASE1-EXEC.md と同じく「実装済み」の節に書く。

## 確認済みの方針

| 項目 | 決めたこと |
|---|---|
| 人物の移動・回転 | 配置モードでも人物を動かせるようにし、腰の回転の不具合を直し、分かりやすい入口も足す |
| 直接置いた小物 | シーン共通（床・物体と同じ）。人物を削除しても残り、どの人物でも拾って持てる |
| 操作欄をしまった後 | 画面端の小さなつまみで出す。スマホは「位置」がないので、つまみで出す・しまうを切り替える |
| 全画面の確認 | スマホ・タブレットは起動時に1度だけ聞く（答えはこのブラウザに記憶）。PC はボタンだけ |
| アイビス風の半透明メニュー | 底のバーのすぐ上に下から出る。高さは画面の 4 割まで（中はスクロール）。同じ項目をもう一度押すか ✕ で閉じる。上の図は触れるまま |
| 底のメニューバー | 3 段を重ねて常に表示（下から 作る/見る/出す → 分類 → タブ）。各段は横スクロール |
| 対象の人物の選択 | 全身図の横に 1 つ（人物の分類と装備のタブで出す）。どのタブにも効く |

## 調べて分かったこと（今のコード）

- 人物ごとの移動・回転は一部ある：ポーズモードで「腰（全体）」を選ぶと、ドラッグ（画面と平行に移動）と3軸ハンドルで人物ごと動き、
  「選んだ関節」と管理タブ「人物の位置と向き」に位置・体の向きのスライダーがある。配置モードでは人物を動かせない。
  - **不具合**：腰を3軸ハンドルの「回転」で回すと、`S.P` だけ回して `S.body`（体の向き）を更新しない（`pose_gizmo.js` の `turn`）。
    関節の角度・関節の限界・スライダーは `bodyRot()` の体の向きで測るので、回したあとはずれる。
- 2人目以降はもうある（`pose_cast.js`）：管理タブの「人物」欄に 人物を追加・複製・削除・一覧。ほかのタブには対象を選ぶ欄がない。
- 小物を置く処理（`putDown`）はある：装備で持たせてから「床・物体に置く」。設置タブは単純な図形（`SOLID_KINDS`）だけ。
  置いた小物は人物の `items` に入るので、人物と一緒に入れ替わり、人物を削除すると消える。
- 全画面表示の処理はない。manifest は `display: standalone`。
- スマホのタッチ用の列（`#touchBar`：操作欄を隠す・Shift・固定・元に戻す・やり直す・横の図・カメラパッド）は文字だけで、アイコンがない。
- 「右→左へ写す」「左→右へ写す」は同じアイコン（`Pose`）。
- 操作欄の出す・しまうは図の右上の `#ovAside`。スマホの分割表示では別に `#vPanels`（`body.full`）がある。2つの仕組みが並んでいる。

### スマホで横の図を出すと崩れる不具合（原因の見当）

- 幅 700px 以下では `.views` が 1 列に固定され（`!important`）、横の図は正面の図の**下に積まれる**。
- ところが `draw()` が横の図に決まった高さ（`fixedH`）を渡すのは `side-top / side-bottom` のときだけ。既定の「右」のままなので、
  分割表示では横の図も正面と同じ「図の領域いっぱいの高さ」を取り、合わせて 2 倍の高さになって `#stage`（`overflow: hidden`）からはみ出す。
- さらに `viewChrome()` は「欄の高さ − 正面の図の高さ」を図のまわりの高さとして測るので、横の図の高さまで含めてしまい、
  正面の図が縮む → 測り直す（`side.style.height` がキーに入っている）→ また縮む、と描くたびに大きさが揺れる。
- 横の図の「置き場所」の絵（右・左・上・下）もスマホでは効かないのに出ている。

## 作業の順序

### 1. 不具合の修正（済：2026-11-02）
1. **スマホで横の図を出したときのレイアウト**（済）
   - 幅 700px 以下で横の図を出すときは、正面の下に積む形（`side-bottom` 扱い）にして、図の領域の高さを正面 6：横 4 で分ける。
     分割表示では `#stage` の高さから、そうでないときは画面の高さから割り当てる。
   - `viewChrome()` は横の図を除いた高さを測る（横の図の高さは計算に入れない）。
   - スマホの横持ち（`max-height: 520px`）は今の左右並びのまま。縦持ちのスマホでは置き場所の絵を隠す。
   - 確認：Pixel 10（約 412×923、DPR 2.625）・iPhone・小さめの Android をエミュレートし、縦と横、分割表示のオン・オフ、横の図のオン・オフを確かめる。
2. **腰を3軸ハンドルで回したときの体の向き**（済）：腰の回転は `S.body` の yaw / pitch / roll に合成して反映する
   （回転後の向きを `bodyRot` と同じ順序の角度に分解。今の `setBodyTurn` と同じく、関節の並びは体の向きと一緒に回す）。

### 2. 小さな見た目の直し
1. **左右の写すボタン**：「左→右へ写す」のアイコンを左右反転して表示（CSS `transform: scaleX(-1)`）。
2. **スマホのボタンにアイコン**：`#touchBar` の各ボタンに PC と同じ作り（アイコン＋短い名前、狭いときはアイコンだけで名前は title と読み上げに残す）。
   ほかに文字だけのボタンが残っていれば同じようにそろえる。
3. **操作欄の出す・しまう**
   - PC：図の右上の `#ovAside` をやめ、「操作欄の位置」の絵のボタンに「隠す」を足す。隠すと、操作欄があった側の画面端に
     「操作欄を出す」の小さなつまみが出る（押すと元の位置に戻る）。
   - スマホ：位置の絵は出さない。図と操作欄の境目につまみを置き、押すたびに出す・しまうを切り替える（`#vPanels` はつまみに置き換え）。
     しまうと 4. のアイビス風の画面になる。

### 3. 全画面表示
- 図の右上の表示スイッチに「全画面」（全画面中は「全画面を解除」）。`document.documentElement.requestFullscreen()`（iPad などは `webkit` 付き）、
  `fullscreenchange` でボタンの表示を合わせる。Esc やブラウザの戻る操作で解除されたときも追う。
- スマホ・タブレットでは、開いたときに「全画面で使いますか？」と1度だけ聞く（`<dialog>`、答えは localStorage に記憶。
  アプリとして開いているとき（`display-mode: standalone / fullscreen`）と `#pose=` のリンクで開いたときの初回表示は聞かない）。
  全画面にはボタンを押す操作が要るので、ダイアログの「全画面にする」ボタンから切り替える。
- iPhone の Safari には全画面の機能がない：ボタンは「ホーム画面に追加すると全画面で使えます」の案内に替える（今の「アプリとして追加」と同じ流れ）。

### 4. 人物ごとの移動・回転
1. **配置モードで人物を動かす**：配置モードで人物の丸（どれでも）をつかむと、その人物ごと床の上を動く（Shift：上下、ホイール：向きを 15° ずつ）。
   3軸ハンドルは腰を中心に、移動（X・Y・Z）と回転（X・Y・Z、体の向きに反映）。固定した関節・ワイヤーの支点も一緒に動く。
   人物の丸をつかんだときは、物体・小物より人物を優先するか、近い方を選ぶ（近い方を選ぶ予定）。
2. **分かりやすい入口**：全身図の腰の所とコンテキストメニューに「人物ごと動かす」。押すと腰を選び、3軸ハンドルを移動にする。
   シーンの一覧の人物の行にも同じ操作を置く。
3. 大きさは今まで通り、身長・頭身などで決める（人物の拡大縮小のハンドルは出さない）。

### 5. 2人目以降と、対象の人物の選択
1. 全身図の横に「対象：1人目 ▾」（人物の分類のタブと装備のタブで出す）。選ぶと `switchFigure` でその人物を編集する。
   人物が1人のときも出し、その中に「＋ 人物を追加」を置く。
2. 管理タブの「人物」欄（追加・複製・削除）は今のまま残し、シーンの一覧の上に「人物を追加」を置いて、管理からも人物を出せることを分かりやすくする。

### 6. 小物を直接置く（シーン共通）
1. **データ**：シーン共通の置いた小物を `S.placed` に持つ（人物の `items` と同じ形、`where: "world"`）。`version: 3` のまま項目を足す。
   - 読み込み：古いデータの人物の `items` のうち `where: "world"` のものは `S.placed` へ移す（読み込み時に1回）。
   - 描画・選択・3軸ハンドル・スナップ・接地は、人物の `items` の置いた小物と同じ処理を `S.placed` にも通す。
   - 「持たせる」：置いた小物を選んで「右手に持つ／左手に持つ」で、いま編集している人物の `items` へ移す。
     人物の小物の「床・物体に置く」は `S.placed` へ移す。
   - 共有リンク（`pose_share.js` の公式 MOD 以外の小物を消す処理）、`api.io.sceneJSON()`、作業ログ・元に戻すにも `S.placed` を含める。
     MODDING.md（-JA）に `placed` を書き足す。
2. **UI**：設置のタブに「小物を置く」欄。装備と同じ分類・検索で選び、置く前のプレビュー（大きさ・長さ・太さ）を出して、
   図の真ん中の床（または物体の上）に置く。置いたあとは配置モードで動かす（今の小物と同じ）。

### 7. スマホのアイビス風の画面（操作欄をしまったとき）
- スマホでつまみから操作欄をしまうと：図が画面いっぱい（ヘッダーも隠す）。底に 3 段のメニューバー（下から 作る/見る/出す、分類、タブ。各段は横スクロール。高さ約 130px）。
- タブを押すと、そのタブの欄がバーの上に半透明の板で出る（`aside` を `position: fixed` にして中身はそのまま使う。高さは画面の 4 割まで、スクロール）。
  同じタブをもう一度押すか ✕ で閉じる。板が出ている間も、上の図は触れる。
- メニューの形は `ui-menu.js` の `TREE` から作る（3 つ目の形として、今の横 3 段・ツリーに足す）。全身図と対象の人物の欄は板の中に出す。
- 図の左上・右上の操作（モード、元に戻す、表示の切り替え）とカメラパッドはそのまま図の上に残す。
- 横持ちでは同じ形にするか、今の左右の分割に戻すかは、作ってから試して決める。

## 実装済み（2026-11-02）

- スマホで横の図を出したときのレイアウト
  - 縦持ちのスマホでは横の図を正面の下に積み、図の領域の高さを正面 6：横 4 で分ける（`sideStacked()`、`viewsRoom()`、`fitCanvas` の `reserve`）。
    PC・タブレットで横の図を上・下に置いたときも、横の図は領域の 4 割まで（かつ画面の高さの約 1/4 まで）
  - `viewChrome()` は図の箱（`.views`）全体を除いて測る。描くたびに大きさが揺れることがなくなった
  - 分割表示しないスマホで、タッチ用の列（横スクロール）がページの幅を 792px まで広げていたのを直した（`#stage, aside { min-width: 0 }`）
  - 縦持ちのスマホでは横の図の置き場所の絵を隠し、置き場所が「隠す」でも「横の図」キーで出る
  - 図の左上・右上のボタンの列は図の高さまでに収め、入りきらない分はスクロール
  - 確認：Pixel 10（412×923）の縦・横、分割表示のオン・オフ。PC（1440×900）とタブレット（1024×1366）で横の図と操作欄の置き場所の組み合わせ
- 腰を3軸ハンドルで回すと、体の向き（`S.body`）も一緒に変わる（`turnBody()`）。回したあとも各関節の角度は変わらない（数値で確認）

## 共通の約束
- 新しい日本語の文言は i18n.js（または各ファイルの英語表）に英語を足す。`?.` と `??` は使わない。
- 見た目は melta UI に従う（色・枠・余白を個別に書かない）。`ui.css` は `npm run css` で作り直す。
- 各段の終わりに `python tools/lint_ui.py`（error 0）と、Playwright で PC・Pixel 10・iPhone の動作確認をする。
  そのために、main の作業ツリーで `git submodule update --init`、`npm install`、`py -m pip install playwright esprima` が要る。
- コミット・push はオーナーがする。各段の終わりに、貼り付けて使えるコマンドを出す。
